## P1：优先修复

### R1 配置解析错误泄露完整密钥原文（已复现）

位置：`src/server.rs:2287`、`src/config.rs:444`。

`ConfigError::Parse` 保留 `toml::de::Error`，其 Debug 包含 `raw: Some(完整输入)`。
服务异常报告使用 `debug={error:#?}`。在配置末尾添加无关的 TOML 语法错误后，PSK 和服务端私钥原文一起进入控制台及 FATAL 日志。
配置结构自身的自定义脱敏 Debug 无法保护这条解析错误链。

根源修复：敏感输入的解析错误应在边界转换为脱敏诊断，只保留位置、分类和不含原文的原因；日志层不能递归打印任意敏感来源错误。
若真实环境曾发生配置解析错误，应将相应日志视为可能含密钥的敏感文件，避免分享，并在确认泄露后轮换密钥。

### R2 停止服务不终止已有连接及其唤醒能力（已复现）

位置：`src/server.rs:1026`、`src/server.rs:1083`、`src/server.rs:1159`、`src/tui.rs:1036`。

关闭标志只控制监听循环；连接线程没有接收该标志，其 JoinHandle 也未被管理。
实测先握手、确认目录，再停止并 join 监听线程，原连接仍收到 accepted=true 的模拟唤醒回执。
与此同时 TUI 将连接数清零并显示服务已停止。旧运行时的 ACL 刷新也随监听循环停止。

根源修复：服务运行句柄必须拥有监听器、所有会话和监测任务的取消与回收；所有任务退出后才报告停止完成。

### R3 热加载授权、握手名单和主机目标来自不同版本（已复现）

位置：`src/server.rs:899`、`src/server.rs:934`、`src/server.rs:1116`、`src/security.rs:841`、`src/server.rs:1741`。

刷新只替换 `access_policy.clients`。握手仍查启动时的 `handshake.allowed_clients`，目标地址仍读启动时的 `snapshot.hosts`。
实测运行中新增的客户端已进入 live ACL，但真实 Noise 握手仍被拒；已保存的新主机 IP 也没有替换实际唤醒目标。

根源修复：使用一次原子发布的已验证运行配置版本，或者明确把不支持热更新的修改置为待重启状态。不能让不同校验阶段读取不同代的授权。

### R4 撤销/编辑先修改内存，保存失败后不回滚（已复现）

位置：`src/tui.rs:449`、`src/tui.rs:531`、`src/tui_core.rs:582`、`src/tui_core.rs:2770`。

撤销先删除界面行和内存 ACL，再保存。实测制造文件共享冲突后，磁盘仍授权原密钥，但界面行、内存 ACL 和内存配置已全部移除。
错误通知不能恢复可重试的操作状态。部署页还无条件显示绿色“已自动保存”，与失败结果矛盾。

根源修复：编辑草稿、持久化配置、已应用运行配置分开管理。验证与原子写入成功后再提交视图和撤销结果；失败保留原状态或明确的未提交草稿。

## P2：功能、安全边界及工程缺陷

### R5 Windows 正常并发读取导致临时全量撤权（已复现）

位置：`src/config.rs:749`、`src/server.rs:918`。

私密读取使用 `share_mode(0)`；正常配置读取之间也互斥。刷新把包括 sharing violation 在内的每种读取错误都解释为清空 ACL。
实测持有一个只读文件句柄时全体授权消失，关闭后又恢复；在线连接会在窗口内断开。TUI 操作和服务刷新可能触发相同竞争。

根源修复：定义支持安全原子替换的文件共享策略，并区分完整有效配置版本、瞬态 I/O 失败和显式撤权。不能单独改成失败时无条件继续授权。

### R6 重连恢复重新计时，与原票据/监测窗口矛盾（两个用例复现）

位置：`src/tui.rs:1218`、`src/tui.rs:1367`、`src/server.rs:511`、`src/server.rs:621`、`src/server.rs:1958`。

恢复同一 attempt 的缓存回执后，TUI 又开始完整 60 秒倒计时，但服务端仍保留原来的 90 秒重试票据和原来的监测截止时间。
两个用例分别确认：已有 20 秒余量被扩回 60 秒；t=40 秒重取回执后按新倒计时在 t=100 秒申请重发会被判 Replay。

根源修复：客户端持有按 operation/attempt 唯一的本地时间状态，恢复回执不等于新执行；恢复、票据和监测窗口须使用一致契约，仍保持客户端决定是否重试。

### R7 部分目标被拒绝仍显示全部完成和绿色 OK（已复现）

位置：`src/tui.rs:1209`、`src/tui.rs:1270`、`src/main.rs:467`、`src/main.rs:511`。

完成判定仅遍历 accepted 集合。两个目标中一个被限流拒绝，另一个上线后，TUI 将流程标为 Complete，进度条显示 OK，尽管另一个目标没有成功。
非交互 CLI 也只比较缩小后的 active_targets，却输出“全部目标已上线”。

根源修复：按原始目标维护已拒绝、等待、在线、超时等结果，聚合为全部成功、部分成功、失败；不能用缩小后的集合替代原始任务目标。

### R8 异常日志和后台线程仍能破坏 TUI（源码路径确认）

位置：`src/logging.rs:224`、`src/tui.rs:80`、`src/tui_core.rs:114`、`src/client.rs:476`、`src/tui.rs:1096`。

写盘失败直接 eprintln；日志接收器失效后回退 stdout。TUI 绘制/事件错误通过 `?` 绕过 `state.shutdown()`，客户端线程也没有受拥有者管理的 join。
任意后台线程 panic 都会执行全局终端恢复，而主 TUI 循环可能继续运行。
客户端事件接收把 Empty 和 Disconnected 都转成 None，后台任务异常消失时不一定撤销“已连接”状态。

根源修复：终端输出由单一所有者管理，生命周期作用域收尾必须覆盖错误退出；日志故障和任务退出作为结构化事件交给拥有者处理。
正常退出分支的上一轮修复存在，但不能据此宣称所有异常路径已解决。

### R9 同步状态探测阻塞同连接的唤醒与撤权响应（源码路径确认）

位置：`src/server.rs:1514`、`src/client.rs:895`、`src/probe.rs:34`。

客户端收到目录后自动请求状态，服务器在连接处理线程里串行探测最多 8 个目标；单目标合法预算可达 5 秒，总等待可接近 40 秒。
期间同一连接的新唤醒无法处理，而客户端执行回执等待只有 15 秒。结果可能是客户端已报超时，服务端随后才处理请求，或请求因时间戳过期被拒。
循环中的撤权和停止检查同样无法抢占当前探测。

根源修复：有界异步探测/任务队列，不在会话控制循环执行整批阻塞 I/O；整体预算需与协议请求和回执期限一致。

### R10 配置允许的时钟误差与在线事件判定不一致（源码路径确认）

位置：`src/client.rs:870`、`src/client.rs:1054`。

握手及 envelope 使用配置的时钟容差，TargetOnline 却硬编码只接受最多未来 5 秒。
例如服务端比客户端快 10 秒、配置容差 30 秒时，握手和回执合法，但正常上线事件被当成非法服务端事件并断开连接。

根源修复：共享时间验证规则，区分发送时间、观察时间和本地单调计时，不能把固定 5 秒当成另一份隐含时钟策略。

### R11 数字 4 在不同入口触发不同业务动作（已复现）

位置：`src/tui.rs:312`、`src/tui_core.rs:530`。

在主机页/凭据页会启动服务；从设置页/部署页跳转时仅切换到运行屏幕。实测设置页按 4 后没有服务线程和监听器。

根源修复：导航产生统一的领域动作，由生产控制器集中处理副作用。不要仅在少数调用入口补 start_server。

### R12 非交互 CLI 失败仍返回成功退出码（源码路径确认）

位置：`src/main.rs:475`、`src/main.rs:516`、`src/main.rs:549`。

全部目标被拒、执行回执超时、两轮等待超时的路径返回 Ok(())，上层进程退出 0，脚本无法据退出码识别失败。
数条 finish 文本直接包含 `{RED}`、`{GREEN}`、`{RESET}` 字面量，未通过 format!；重定向输出路径还继续使用光标/颜色转义。

根源修复：UI/CLI 共享同一任务结果模型，退出码从结果派生；交互与非交互渲染作为不同输出实现。

### R13 DNS 只尝试第一个地址，双栈没有地址回退（源码路径确认）

位置：`src/client.rs:1215`、`src/client.rs:520`。

域名解析后只取首个可用格式地址，重试仍从头解析/取首地址。若 AAAA 在前但 IPv6 不通、A 可达，客户端可能持续失败而不尝试 IPv4。

根源修复：连接状态机管理一个有界候选地址集合和总时间预算，尝试失败时推进到其他候选地址。

### R14 私密文件读取承诺在两平台上并不等价（源码路径确认）

位置：`src/config.rs:735`、`src/server.rs:2262`、`README.md`“部署与日志”。

Windows 分支只检查 regular file、大小和 reparse 属性，没有检查文件 DACL、所有者或硬链接数，因此导入的宽权限私钥文件仍被接受。
服务启动在安全打开前先 canonicalize 配置路径，最终符号链接被提前解析，随后 O_NOFOLLOW 检查不到原链接。这与 README 的统一拒绝链接承诺不符。
这里没有声称能够远程越权；它是本地文件威胁模型和实现之间的缺口。

根源修复：明确平台对应的句柄级权限/身份检查，不在检查前抹掉路径别名信息；文档只承诺实际执行的策略。

### R15 凭据删除验证和实际删除不绑定同一文件（源码路径确认）

位置：`src/client.rs:261`、`src/client.rs:281`。

读取和验证公钥后读句柄已关闭，随后按路径 remove_file。若目录项在两步之间被其他有写权限的本地进程替换，删除的并非已验证文件。
此风险要求能修改该目录项的本地并发参与者，不是未认证网络攻击。

根源修复：绑定文件身份的删除/隔离流程，明确每个平台的并发替换语义和父目录权限前提；现有“身份校验后删除”测试未覆盖竞争窗口。

### R16 Linux 构建配置屏蔽链接器诊断（配置确认）

位置：`.cargo/config.toml:5`。

`rustflags = ["-A", "linker-messages"]` 屏蔽这一整类诊断，并非只屏蔽注释提到的一条 Zig 消息，违背 AGENTS.md 的不跳过警告规则。
本轮交叉编译通过不能用于证明链接阶段无警告。

根源修复：处理工具链/链接参数的实际不兼容，并恢复链接器诊断。不要用 lint 级别开关证明“零警告”。

### R17 Windows 部署指令不能直接复制到 PowerShell（解析器复现）

位置：`src/tui.rs:1523`。

生成 `"C:\...\RemoteOpenPower.exe" --server ...`，缺少 PowerShell 调用运算符 `&`。
本机 PowerShell 解析器确认报 UnexpectedToken 和 OperatorRequiresVariableOrProperty。

根源修复：根据明确的目标 shell 输出并引用参数；PowerShell 指令应使用 `&` 和适当的引号转义，不混用 cmd.exe 的语法。
